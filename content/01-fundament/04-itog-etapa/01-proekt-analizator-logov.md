# Теория

## Зачем нужен проект

До сих пор ты решал задачи, где было сказано, что делать. В проекте ты сам
решаешь, как разбить работу, как назвать функции и что считать готовым.
Это и есть главное умение разработчика.

Проект объединяет всё, что было на этапе: Python (строки, словари, функции,
файлы, исключения, JSON), Linux (терминал, права, скрипты) и Git.

## Что нужно сделать

Программа `logscan` читает журнал событий сетевого оборудования
и выводит сводку.

Пример запуска и вывода:

```text
$ python3 logscan.py network.log

Файл: network.log
Записей: 1240 (пропущено некорректных строк: 3)
Период: 2026-01-15 00:00:04 — 2026-01-15 23:59:51

По уровням:
  INFO      1012
  WARNING    187
  ERROR       41

Устройства с наибольшим числом ошибок:
  sw-access-07    14
  sw-core-1        9
  rt-border-1      6
```

Формат строки журнала придумай сам или возьми такой:

```text
2026-01-15 14:32:07 sw-core-1 ERROR Port Gi0/5 is down
```

> Используй только выдуманные данные. Настоящие журналы с рабочего
> оборудования в учебный проект и тем более на GitHub попадать не должны.

## Обязательные возможности

1. Путь к файлу передаётся аргументом командной строки.
2. Подсчёт записей по уровням и по устройствам.
3. Три устройства с наибольшим числом ошибок.
4. Опция `--level ERROR` — показать только записи заданного уровня.
5. Опция `--json report.json` — сохранить сводку в файл.
6. Понятные сообщения, если файла нет или он пуст.

## Возможности по желанию

- фильтр по устройству и по интервалу времени;
- поиск «хлопающих» портов: много переходов `up`/`down` за короткое время;
- цветной вывод через библиотеку `rich`;
- скрипт `generate_log.py`, создающий тестовый журнал нужного размера.

## Как подойти к работе

**1. Начни с самого простого.** Первая версия просто читает файл и печатает
количество строк. Это уже коммит.

**2. Добавляй по одной возможности.** Разбор строки → подсчёт по уровням →
подсчёт по устройствам → аргументы → JSON. После каждого шага программа работает.

**3. Раздели код на части.**

```text
logscan/
├── logscan.py          # точка входа: аргументы и вывод
├── parser.py           # разбор строк журнала
├── stats.py            # подсчёты
├── sample.log          # небольшой пример журнала
├── requirements.txt
├── .gitignore
└── README.md
```

**4. Функции возвращают данные, а не печатают.** Тогда один и тот же расчёт
можно и вывести на экран, и сохранить в JSON.

## Аргументы командной строки

Для разбора аргументов в стандартной библиотеке есть модуль `argparse`.

```python
import argparse


def parse_args():
    parser = argparse.ArgumentParser(description="Анализ журнала сетевых событий")
    parser.add_argument("path", help="путь к файлу журнала")
    parser.add_argument("--level", help="показать только записи этого уровня")
    parser.add_argument("--json", dest="json_path", help="сохранить сводку в файл")
    return parser.parse_args()


args = parse_args()
print(args.path, args.level, args.json_path)
```

Бонусом `argparse` сам создаёт справку: `python3 logscan.py --help`.

## Когда застрял

1. Сформулируй вслух, что именно не получается.
2. Уменьши задачу: проверь проблемное место на трёх строках данных.
3. Прочитай сообщение об ошибке целиком, снизу вверх.
4. Сделай перерыв. Решение часто приходит во время прогулки.
5. Спроси — у нейросети или у сообщества. Но сначала сам потрать на задачу
   хотя бы двадцать минут: так запоминается намного лучше.

# Практика

**Шаг 1.** Создай на GitHub репозиторий `logscan`, склонируй его, создай
виртуальное окружение и `.gitignore`.

**Шаг 2.** Напиши `generate_log.py` или подготовь файл `sample.log`
на 50–100 строк с несколькими намеренно испорченными строками.

**Шаг 3.** Реализуй обязательные возможности по одной. Каждую — в отдельной
ветке, с pull request и слиянием в `main`.

**Шаг 4.** Проверь программу на плохих данных: пустой файл, несуществующий
путь, файл из одних некорректных строк, очень большой файл.

**Шаг 5.** Приведи код в порядок: `ruff check` и `ruff format`,
понятные имена, строки документации у функций.

**Шаг 6.** Напиши `README.md`: что делает программа, как установить,
пример запуска с выводом, описание опций.

**Шаг 7.** Закрепи репозиторий в профиле GitHub.

**Шаг 8 (со звёздочкой).** Напиши bash-скрипт, который запускает анализ
для всех файлов `.log` в папке и складывает отчёты в `reports/`.
Настрой его запуск по расписанию.

# Теория

## Зачем нужен Git

Знакомая картина: `config_final.txt`, `config_final2.txt`, `config_final_точно.txt`.
Git решает эту задачу правильно. Он хранит историю изменений проекта и позволяет:

- вернуться к любому сохранённому состоянию;
- увидеть, что, когда и зачем менялось;
- пробовать идеи, не боясь сломать рабочую версию;
- работать над одним кодом нескольким людям.

Для сетевого инженера ближайшая аналогия — архив конфигураций оборудования
с возможностью сравнить версии и откатиться.

## Первая настройка

Выполняется один раз на компьютере:

```bash
git config --global user.name "Иван Иванов"
git config --global user.email "ivan@example.com"
git config --global init.defaultBranch main
```

Имя и почта записываются в каждый коммит.

## Создание репозитория

```bash
cd ~/study
git init
```

В папке появилась скрытая папка `.git` — в ней Git хранит всю историю.
Удалишь её — история исчезнет, а файлы останутся.

## Три состояния файла

Это главная идея Git. Изменение проходит три шага:

```text
рабочая папка  ──git add──>  индекс  ──git commit──>  история
 (изменено)                (подготовлено)            (сохранено)
```

- **Рабочая папка** — файлы, как они есть на диске.
- **Индекс** — список изменений, которые войдут в следующий коммит.
- **История** — цепочка сохранённых коммитов.

Индекс нужен, чтобы выбирать: из пяти изменённых файлов в коммит можно
включить только два, относящихся к одной задаче.

## Основной цикл работы

```bash
git status                  # что изменилось
git add hello.py            # подготовить один файл
git add .                   # подготовить всё в текущей папке
git commit -m "Добавить программу приветствия"
git log --oneline           # история: по одной строке на коммит
```

`git status` — самая частая команда. Выполняй её перед каждым действием
и после него: она подсказывает, что происходит и что делать дальше.

## Что такое коммит

Коммит — снимок всего проекта в определённый момент. У него есть автор,
дата, сообщение и уникальный идентификатор — строка вроде `a1b2c3d`.

Хороший коммит содержит одно логическое изменение. «Добавить проверку
IP-адреса» — хорошо. «Разные правки за день» — плохо.

## Сообщения коммитов

Сообщение отвечает на вопрос «что делает этот коммит».

| Плохо | Хорошо |
|---|---|
| `fix` | `Исправить деление на ноль при пустом списке` |
| `правки` | `Добавить чтение устройств из JSON` |
| `asdf` | `Вынести проверку адреса в отдельную функцию` |

Через полгода история с такими сообщениями читается как журнал работ.

# Практика

**Задание 1.** Настрой имя и почту. Создай репозиторий в папке `~/study`.

**Задание 2.** Выполни `git status` и прочитай вывод. Добавь в индекс
только папку `python` и сделай первый коммит. Затем отдельным коммитом
добавь папку `linux`.

**Задание 3.** Измени два файла. Сделай из этих изменений два отдельных
коммита с осмысленными сообщениями.

**Задание 4.** Посмотри историю через `git log` и `git log --oneline`.
Найди идентификатор первого коммита.

**Задание 5.** Пройди первые четыре урока раздела «Введение» в тренажёре
Learn Git Branching.

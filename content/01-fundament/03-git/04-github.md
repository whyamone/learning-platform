# Теория

## Git и GitHub — не одно и то же

**Git** — программа на твоём компьютере. **GitHub** — сайт, где хранятся
копии репозиториев. Копия на сервере называется **удалённым репозиторием**.

Зачем он нужен: резервная копия, работа с нескольких компьютеров,
совместная разработка и витрина твоих проектов для работодателя.

## Подключение по SSH

Ключ ты создал в теме про SSH. Осталось сообщить его GitHub.

```bash
cat ~/.ssh/id_ed25519.pub
```

Скопируй вывод целиком. На GitHub открой **Settings → SSH and GPG keys →
New SSH key**, вставь ключ и сохрани. Проверка:

```bash
ssh -T git@github.com
```

Ответ `Hi имя! You've successfully authenticated` означает, что всё настроено.

## Отправка своего репозитория

Создай на GitHub пустой репозиторий (без README) и свяжи его с локальным:

```bash
git remote add origin git@github.com:ИМЯ/study.git
git remote -v                     # проверить адрес
git push -u origin main
```

`origin` — имя, под которым Git запомнил адрес сервера. Опция `-u` связывает
локальную ветку с удалённой: дальше достаточно писать `git push`.

## Ежедневная работа

```bash
git pull                # получить чужие изменения и влить в свою ветку
# ...работа, коммиты...
git push                # отправить свои коммиты
```

Привычка: начинать работу с `git pull`, заканчивать `git push`.

## fetch и pull

- `git fetch` скачивает новые коммиты, но не трогает твои файлы.
  Можно посмотреть, что пришло: `git log main..origin/main`.
- `git pull` — это `fetch` и сразу `merge`.

`origin/main` — локальная копия сведений о том, где находится ветка
`main` на сервере. Она обновляется при `fetch` и `pull`.

## Если push отклонён

```text
! [rejected]  main -> main (fetch first)
```

На сервере есть коммиты, которых нет у тебя. Сначала получи их:

```bash
git pull
git push
```

> `git push --force` перезаписывает историю на сервере и может уничтожить
> чужую работу. В общих ветках им не пользуются.

## Клонирование

```bash
git clone git@github.com:ИМЯ/study.git
git clone https://github.com/python/cpython.git
```

Клонирование скачивает весь репозиторий с историей и сразу настраивает `origin`.
Чужой открытый проект можно клонировать по HTTPS без ключа.

## Что не должно попасть на GitHub

Перед первой отправкой проверь `.gitignore`. В открытый репозиторий
не должны попасть пароли, ключи, файлы `.env`, а также рабочие конфигурации
с реальными адресами и именами. Для тебя, работающего в закрытом контуре,
это особенно важно: в учебных примерах используй выдуманные данные.

и найди историю коммитов.

**Задание 4.** Склонируй свой репозиторий в другую папку. Сделай коммит

в обеих копиях и попробуй отправить вторую. Реши проблему.

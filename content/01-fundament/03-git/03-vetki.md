# Теория

## Что такое ветка

Ветка — отдельная линия разработки. В ней можно делать что угодно,
не затрагивая основную версию.

Технически ветка — это просто **указатель на коммит**. Создание ветки
не копирует файлы, поэтому происходит мгновенно. Основная ветка обычно
называется `main`.

```text
main:     A ── B ── C
                     \
feature:              D ── E
```

## Работа с ветками

```bash
git branch                     # список веток; текущая помечена звёздочкой
git switch -c add-json         # создать ветку и перейти в неё
git switch main                # вернуться в main
git branch -d add-json         # удалить ветку после слияния
```

При переключении Git меняет файлы в рабочей папке на состояние выбранной ветки.

> В старых руководствах вместо `git switch` встречается `git checkout`.
> Это то же самое: `git checkout -b имя` равнозначно `git switch -c имя`.

## Обычный порядок работы

1. Создать ветку под задачу: `git switch -c fix-ip-check`.
2. Сделать в ней один или несколько коммитов.
3. Вернуться в основную ветку: `git switch main`.
4. Слить: `git merge fix-ip-check`.
5. Удалить ветку: `git branch -d fix-ip-check`.

Так основная ветка всегда остаётся рабочей, а незаконченное живёт отдельно.
Эта учебная платформа разрабатывается так же: работа идёт в ветке `develop`,
проверенное попадает в `main`.

## Слияние

```bash
git switch main
git merge add-json
```

Возможны два исхода.

**Перемотка (fast-forward).** В `main` за это время ничего не менялось.
Git просто передвигает указатель `main` вперёд.

**Коммит слияния.** Обе ветки ушли вперёд. Git создаёт особый коммит
с двумя родителями, объединяющий изменения.

## Конфликты

Если в обеих ветках изменена одна и та же строка, Git не знает, какой
вариант правильный, и останавливается:

```text
CONFLICT (content): Merge conflict in netutils.py
Automatic merge failed; fix conflicts and then commit the result.
```

В файле появляются метки:

```text
<<<<<<< HEAD
    return 1 <= number <= 4094
=======
    return 0 < number < 4095
>>>>>>> fix-vlan-check
```

Между `<<<<<<<` и `=======` — вариант текущей ветки, между `=======`
и `>>>>>>>` — вариант вливаемой.

Как разрешить конфликт:

1. Открой файл и оставь правильный вариант (один из двух или их сочетание).
2. Удали все три строки с метками.
3. Выполни `git add файл`.
4. Заверши слияние: `git commit`.

Если запутался, слияние можно отменить: `git merge --abort`.

Конфликт — не авария, а обычная рабочая ситуация. VS Code показывает
оба варианта с кнопками выбора.

## Как называть ветки

Имя должно описывать задачу: `add-json-export`, `fix-ip-validation`.
Часто добавляют приставку: `feature/json-export`, `fix/ip-validation`.

# Практика

**Задание 1.** Создай ветку `add-readme`, добавь в ней файл `README.md`
с описанием репозитория, закоммить. Вернись в `main` и убедись,
что файла там нет. Слей ветку и удали её.

**Задание 2.** Создай ветку, сделай в ней два коммита. В `main` сделай
ещё один коммит в другом файле. Слей и посмотри историю
через `git log --oneline --graph`.

**Задание 3.** Создай конфликт намеренно: измени одну и ту же строку
по-разному в двух ветках. Попробуй слить, разреши конфликт и заверши слияние.

**Задание 4.** Повтори задание 3, но на этот раз отмени слияние
через `git merge --abort`.

**Задание 5.** Пройди в тренажёре Learn Git Branching уроки про ветки
и слияние из раздела «Введение».

**Задание 6 (со звёздочкой).** Выясни, что делает `git stash`,
и воспользуйся им: начни правку, спрячь её, переключись на другую ветку,
вернись и достань спрятанное.

# Теория

## Ошибки, о которых Python молчит

Синтаксические ошибки и исключения Python показывает сам. Труднее всего
**логические ошибки**: программа работает, но выдаёт неверный результат.

```python
def average(numbers):
    total = 0
    for number in numbers:
        total += number
    return total / len(numbers) - 1      # лишнее «- 1»

print(average([10, 20, 30]))    # 19.0 вместо 20.0
```

Никакого сообщения об ошибке нет. Искать придётся самому.

## Порядок поиска

1. **Воспроизведи.** Найди входные данные, на которых ошибка проявляется всегда.
2. **Уменьши.** Упрости пример до минимума: три числа вместо тысячи строк лога.
3. **Сформулируй ожидание.** Что должно получиться и что получается на деле.
4. **Сузь место.** Проверь промежуточные значения и найди первое неверное.
5. **Исправь и проверь** на том же примере и ещё на паре других.

## Отладочная печать

Самый простой способ — вывести промежуточные значения.

```python
def average(numbers):
    total = 0
    for number in numbers:
        total += number
        print(f"{number=} {total=}")     # временная отладочная строка
    print(f"{len(numbers)=}")
    return total / len(numbers) - 1
```

Запись `f"{total=}"` печатает и имя, и значение: `total=30`. Удобно и коротко.

Когда ошибка найдена, отладочные строки удаляют.

## Отладчик

Отладчик останавливает программу в выбранном месте и позволяет выполнять её
по шагам, наблюдая за переменными.

Встроенный отладчик включается функцией `breakpoint()`:

```python
def average(numbers):
    total = 0
    for number in numbers:
        total += number
    breakpoint()                  # здесь программа остановится
    return total / len(numbers) - 1
```

После остановки появится приглашение `(Pdb)`. Основные команды:

| Команда | Что делает |
|---|---|
| `p total` | показать значение переменной |
| `n` | выполнить следующую строку |
| `s` | зайти внутрь функции |
| `c` | продолжить до следующей остановки |
| `l` | показать код вокруг текущей строки |
| `q` | выйти |

В редакторе VS Code то же самое делается мышью: щелчок слева от номера строки
ставит точку останова, клавиша F5 запускает отладку.

## Метод утёнка

Объясни вслух, строку за строкой, что делает твой код — резиновой игрушке,
коллеге или нейросети. Очень часто ошибка находится прямо во время объяснения:
ты замечаешь, что код делает не то, о чём ты рассказываешь.

## Зачем нужен единый стиль

Код читают гораздо чаще, чем пишут. Чтобы чужой код читался так же легко,
как свой, в сообществе Python принят общий стандарт — **PEP 8**.

Главное из него:

- отступ — четыре пробела;
- имена переменных и функций — `snake_case`, классов — `CamelCase`,
  констант — `UPPER_CASE`;
- пробелы вокруг операторов: `x = a + b`, а не `x=a+b`;
- пробел после запятой: `print(a, b)`;
- между функциями — две пустые строки;
- строка не длиннее 79–100 символов;
- импорты — в начале файла.

```python
# Плохо
def Calc(a,b):
  x=a+b
  return x

# Хорошо
def calculate_total(first, second):
    total = first + second
    return total
```

## Имена важнее комментариев

```python
# Плохо: без комментария не понять
d = t / s    # делим время на скорость

# Хорошо: код объясняет себя сам
duration = distance / speed
```

Комментарий должен объяснять **почему**, а не **что**. Что делает код —
видно из самого кода, если имена выбраны хорошо.

## Линтер и форматтер

Запоминать все правила не нужно: за стилем следят программы.

- **Линтер** находит ошибки и нарушения стиля.
- **Форматтер** сам переписывает код в принятом виде.

Самый популярный инструмент сейчас — `ruff`, он умеет и то и другое.
Установи его в виртуальное окружение:

```bash
pip install ruff
```

```bash
ruff check .         # показать проблемы
ruff check --fix .   # исправить то, что можно исправить автоматически
ruff format .        # привести оформление к единому виду
```

Эта учебная платформа тоже проверяется через `ruff` — посмотри команду
`make lint` в её `Makefile`.

## Редактор VS Code

До сих пор хватало `nano`. Для программ длиннее пары экранов нужен
настоящий редактор кода.

1. Установи VS Code в Windows с сайта code.visualstudio.com.
2. В VS Code установи расширение **WSL** (вкладка Extensions).
3. В терминале Ubuntu перейди в папку проекта и выполни `code .`

VS Code откроется и будет работать с файлами внутри Ubuntu. Затем установи
расширения **Python** и **Ruff**: появятся подсветка ошибок, автодополнение
и форматирование при сохранении.

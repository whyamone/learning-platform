# Теория

## Два вида ошибок

**Синтаксическая ошибка** — нарушены правила записи. Python находит её
до запуска, и программа не стартует вообще.

**Исключение** — ошибка во время выполнения. Код записан верно,
но что-то пошло не так: файла нет, пользователь ввёл буквы вместо числа,
сервер не ответил.

```python
number = int("abc")
```

```text
Traceback (most recent call last):
  File "example.py", line 1, in <module>
    number = int("abc")
ValueError: invalid literal for int() with base 10: 'abc'
```

## Как читать трассировку

Сообщение об ошибке называется трассировкой. Читай его **снизу вверх**:

1. Последняя строка — тип исключения и описание. Самое важное.
2. Выше — файл и номер строки, где ошибка случилась.
3. Ещё выше — цепочка вызовов функций, которая к ней привела.

Если описание непонятно, скопируй последнюю строку в поисковик или спроси
у нейросети — ошибки Python хорошо изучены.

## Частые исключения

| Исключение | Когда возникает |
|---|---|
| `ValueError` | значение не подходит: `int("abc")` |
| `TypeError` | не тот тип: `"a" + 1` |
| `KeyError` | в словаре нет ключа |
| `IndexError` | в списке нет элемента с таким индексом |
| `ZeroDivisionError` | деление на ноль |
| `FileNotFoundError` | файл не найден |
| `AttributeError` | у объекта нет такого метода или свойства |
| `ModuleNotFoundError` | модуль не установлен или имя с опечаткой |

## try и except

Чтобы программа не падала, опасный код помещают в блок `try`.

```python
try:
    count = int(input("Сколько портов? "))
    print(f"Вдвое больше портов: {count * 2}")
except ValueError:
    print("Нужно ввести целое число")

print("Программа продолжает работу")
```

Если в блоке `try` возникает `ValueError`, остаток блока пропускается
и выполняется `except`. Если ошибки нет — `except` пропускается.

## Повторный запрос

Самое частое применение — спрашивать, пока не введут корректное значение:

```python
def ask_number(prompt):
    """Запрашивать число, пока пользователь не введёт корректное."""
    while True:
        try:
            return int(input(prompt))
        except ValueError:
            print("Это не число, попробуй ещё раз")


vlan = ask_number("Номер VLAN: ")
```

## Несколько видов ошибок

```python
try:
    total = int(input("Всего пакетов: "))
    lost = int(input("Потеряно: "))
    print(f"Потери: {lost / total * 100:.1f}%")
except ValueError:
    print("Нужно вводить целые числа")
except ZeroDivisionError:
    print("Количество пакетов не может быть нулём")
```

Объект ошибки можно получить через `as` — в нём есть текст сообщения:

```python
try:
    with open("config.txt", encoding="utf-8") as file:
        text = file.read()
except FileNotFoundError as error:
    print(f"Не удалось прочитать файл: {error}")
```

## Не лови всё подряд

```python
try:
    do_something()
except:              # так делать не надо
    pass
```

Такой код глотает любые ошибки, включая опечатки в именах переменных.
Программа молча делает не то, а ты не знаешь почему.

Правила:

- перехватывай **конкретные** исключения, которые умеешь обработать;
- в `except` всегда что-то делай: сообщи, запиши в журнал, верни запасное значение;
- если не знаешь, что делать с ошибкой, — не лови её. Пусть программа упадёт
  с понятной трассировкой: это лучше, чем неправильный результат.

## else и finally

```python
try:
    file = open("data.txt", encoding="utf-8")
except FileNotFoundError:
    print("Файл не найден")
else:
    # выполняется, только если ошибки НЕ было
    print(file.read())
    file.close()
finally:
    # выполняется всегда: и при ошибке, и без неё
    print("Проверка завершена")
```

`finally` нужен для уборки: закрыть соединение, удалить временный файл.

## raise — вызвать исключение самому

Если функция получила данные, с которыми не может работать, она должна
сообщить об этом, а не возвращать ерунду.

```python
def hosts_in_subnet(prefix):
    """Вернуть количество адресов узлов для маски от /1 до /30."""
    if not 1 <= prefix <= 30:
        raise ValueError(f"Недопустимая маска: /{prefix}")
    return 2 ** (32 - prefix) - 2


try:
    print(hosts_in_subnet(24))     # 254
    print(hosts_in_subnet(40))
except ValueError as error:
    print(f"Ошибка: {error}")
```

Так функция остаётся честной: либо верный результат, либо ясная ошибка.
А что делать с ошибкой, решает тот, кто функцию вызвал.

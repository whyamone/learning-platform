# Теория

## Что такое переменная окружения

У каждого процесса есть набор именованных значений — **окружение**.
Через него программам передают настройки: какой язык использовать,
где домашняя папка, какой ключ доступа к сервису.

```bash
echo $HOME            # значение одной переменной
echo $USER
env                   # все переменные окружения
env | grep LANG       # найти нужную
```

Знак `$` перед именем означает «подставь значение». Имена принято
писать заглавными буквами.

| Переменная | Что хранит |
|---|---|
| `HOME` | домашняя папка |
| `USER` | имя пользователя |
| `PWD` | текущая папка |
| `SHELL` | используемая оболочка |
| `LANG` | язык и кодировка |
| `PATH` | где искать команды |

## Создание переменных

```bash
SERVER=192.168.1.10           # обычная переменная оболочки
echo $SERVER

export API_URL=http://localhost:8000    # переменная окружения
```

Вокруг знака `=` не должно быть пробелов. Запись `SERVER = 1` оболочка
поймёт как команду `SERVER` с двумя аргументами.

Разница между двумя видами: обычная переменная видна только в текущей
оболочке. Переменная, объявленная через `export`, передаётся всем программам,
запущенным из этой оболочки.

```bash
NAME=test
python3 -c 'import os; print(os.environ.get("NAME"))'     # None

export NAME=test
python3 -c 'import os; print(os.environ.get("NAME"))'     # test
```

Можно задать переменную только для одной команды:

```bash
DEBUG=1 python3 app.py
```

## PATH — где оболочка ищет команды

Когда ты набираешь `ls`, оболочка должна найти файл программы. Она ищет его
в каталогах, перечисленных в переменной `PATH`, по порядку.

```bash
echo $PATH
```

```text
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

Каталоги разделены двоеточием. Оболочка проверяет их слева направо
и запускает первую найденную программу с нужным именем.

```bash
which ls              # /usr/bin/ls — где нашлась команда
which python3
```

Отсюда два следствия:

- `command not found` означает, что программы нет ни в одном каталоге из `PATH`.
- Скрипт в текущей папке запускается как `./script.sh`, потому что текущая
  папка в `PATH` не входит.

Добавить свой каталог в `PATH`:

```bash
export PATH="$HOME/bin:$PATH"
```

Запись читается так: новый `PATH` — это `~/bin`, затем двоеточие,
затем прежнее содержимое. Забудешь `:$PATH` — потеряешь все остальные каталоги,
и перестанут работать даже `ls` и `cd`. Лечится открытием нового окна терминала.

Виртуальное окружение Python устроено именно так: команда
`source .venv/bin/activate` ставит папку `.venv/bin` в начало `PATH`,
и слово `python` начинает означать Python из окружения.

## Как сохранить настройки: ~/.bashrc

Переменные, заданные в терминале, исчезают при его закрытии. Чтобы они
появлялись всегда, их записывают в файл `~/.bashrc` — он выполняется
при каждом запуске оболочки.

```bash
nano ~/.bashrc
```

Допиши в конец файла:

```bash
# Мои настройки
export EDITOR=nano
alias ll='ls -lah'
alias gs='git status'
```

Чтобы изменения подействовали в уже открытом терминале:

```bash
source ~/.bashrc
```

**Псевдоним** (alias) — короткое имя для длинной команды. Теперь `ll`
равнозначно `ls -lah`.

## Переменные окружения в Python

```python
import os

home = os.environ["HOME"]                        # ошибка, если переменной нет
debug = os.environ.get("DEBUG", "0")             # значение по умолчанию
api_url = os.environ.get("API_URL", "http://localhost:8000")

print(home, debug, api_url)
```

Значение всегда строка. Число нужно преобразовать: `int(os.environ.get("PORT", "8000"))`.

## Секреты и файл .env

Пароли, токены и ключи доступа **никогда** не пишут в коде. Код попадает
в git и на GitHub, и секрет становится доступен всем. Ключи от платных
сервисов, попавшие в открытый репозиторий, находят и используют автоматические
программы — за считаные минуты.

Вместо этого секреты передают через переменные окружения. Для удобства
их записывают в файл `.env` в папке проекта:

```text
API_KEY=sk-example-not-a-real-key
DATABASE_URL=sqlite:///data/app.db
DEBUG=1
```

Правила работы с `.env`:

- файл `.env` добавляют в `.gitignore`, чтобы он не попал в репозиторий;
- в репозиторий кладут `.env.example` — тот же список переменных,
  но без настоящих значений;
- программа читает переменные из окружения, а не из кода.

Так устроена и эта учебная платформа: посмотри файлы `.env.example`
и `app/config.py`.

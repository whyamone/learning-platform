# Теория

## Пакеты и репозитории

В Windows программы скачивают с сайтов и запускают установщик. В Linux
принят другой подход: программы берут из **репозитория** — проверенного
хранилища, которое ведут разработчики дистрибутива.

**Пакет** — это архив с программой и описанием: версия, список файлов,
от каких других пакетов она зависит.

**Менеджер пакетов** скачивает пакет, ставит всё, что ему нужно для работы,
и запоминает, какие файлы куда положил. В Ubuntu и Debian это `apt`.

Преимущества такого подхода: один способ установки для всего, обновление
всех программ одной командой, меньше риска поставить вредоносную программу.

## Обновление

```bash
sudo apt update       # скачать свежий список доступных пакетов
sudo apt upgrade      # обновить установленные программы
```

Эти две команды легко перепутать:

- `update` ничего не устанавливает. Она только узнаёт, какие версии
  доступны в репозитории.
- `upgrade` ставит новые версии — на основе списка, полученного через `update`.

Поэтому их выполняют парой, в этом порядке. Частая запись в одну строку:

```bash
sudo apt update && sudo apt upgrade -y
```

`&&` означает «выполнить вторую команду, только если первая завершилась успешно».
Опция `-y` заранее отвечает «да» на вопрос о подтверждении.

## Поиск и сведения

```bash
apt search htop           # искать пакет по названию и описанию
apt show htop             # подробные сведения: версия, размер, описание
apt list --installed      # все установленные пакеты
apt list --upgradable     # для чего есть обновления
```

Для этих команд `sudo` не нужен: они ничего не меняют.

## Установка и удаление

```bash
sudo apt install htop                 # установить
sudo apt install -y tree curl git     # несколько сразу, без вопросов
sudo apt remove htop                  # удалить программу, настройки оставить
sudo apt purge htop                   # удалить вместе с настройками
sudo apt autoremove                   # удалить зависимости, которые больше не нужны
```

Перед установкой `apt` покажет, что именно собирается поставить
и сколько места это займёт. Читай этот список: если вместе с маленькой
утилитой предлагается сотня пакетов, стоит остановиться и разобраться.

## Откуда взялась команда

```bash
which python3             # где лежит исполняемый файл
dpkg -S /usr/bin/python3  # какому пакету принадлежит файл
dpkg -L htop              # какие файлы установил пакет
```

Если команда не найдена, Ubuntu часто сама подсказывает, какой пакет установить:

```text
Command 'tree' not found, but can be installed with:
sudo apt install tree
```

## Полезный набор утилит

Эти программы пригодятся в следующих темах:

```bash
sudo apt install -y htop tree curl wget git tmux jq unzip net-tools dnsutils
```

| Пакет | Что даёт |
|---|---|
| `htop` | удобный монитор процессов |
| `tree` | вывод папок в виде дерева |
| `curl`, `wget` | запросы к сайтам и скачивание файлов |
| `git` | система контроля версий |
| `tmux` | несколько сеансов терминала в одном окне |
| `jq` | разбор и форматирование JSON |
| `dnsutils` | команды `dig` и `nslookup` |
| `net-tools` | старые сетевые команды `ifconfig`, `netstat` |

## Другие способы установки

Не всё есть в репозитории Ubuntu, и версии там бывают не самые новые.

| Способ | Когда используется |
|---|---|
| `apt` | системные программы и утилиты — основной способ |
| `pip` | библиотеки Python — в виртуальное окружение проекта |
| `snap` | программы в изолированной упаковке |
| скрипт с сайта программы | когда разработчик предлагает свой установщик |
| Docker | программа запускается в контейнере и в систему не ставится |

> Команды вида `curl https://... | sudo bash` выполняют на твоём компьютере
> чужой скрипт с правами администратора. Используй их только с официальных
> сайтов известных программ и по возможности сначала прочитай скрипт.

Не смешивай `apt` и `pip`: системный Python принадлежит Ubuntu, и ставить
в него библиотеки через `pip` нельзя. Библиотеки для своих программ
всегда ставятся в виртуальное окружение.

## Где настроены репозитории

Список репозиториев хранится в каталоге `/etc/apt/sources.list.d/`
и в файле `/etc/apt/sources.list`. На работе в закрытом контуре вместо
интернет-адресов там обычно указано внутреннее зеркало.

**Задание 1.** Обнови список пакетов и посмотри, для каких программ есть
обновления. Обнови систему.

**Задание 2.** Найди через `apt search` программу для вывода каталогов
в виде дерева. Посмотри сведения о ней, установи и выведи дерево папки `~/study`.

**Задание 3.** Установи набор утилит из теории. Запусти `htop`
и сравни с `top`.

**Задание 4.** Выясни, каким пакетом установлены команды `ls`, `python3`
и `ssh`. Посмотри, какие файлы поставил пакет `tree`.

**Задание 5.** Посчитай, сколько пакетов установлено в системе.
Подсказка: конвейер с `wc -l`.

**Задание 6.** Установи программу `cowsay`, попробуй её и удали вместе
с настройками. Убедись, что команда больше не находится, и выполни `autoremove`.

**Задание 7 (со звёздочкой).** Посмотри содержимое `/etc/apt/sources.list.d/`.

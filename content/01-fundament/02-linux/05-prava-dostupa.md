# Теория

## Пользователи и группы

Linux — многопользовательская система. У каждого файла есть **владелец**
и **группа**. Права проверяются при каждом обращении к файлу.

```bash
whoami              # имя текущего пользователя
id                  # номер пользователя и список его групп
groups              # только группы
```

Сведения о пользователях хранятся в `/etc/passwd`, о группах — в `/etc/group`.

## Как читать ls -l

```bash
ls -l
```

```text
-rw-r--r-- 1 ivan ivan  220 янв 15 10:02 notes.txt
drwxr-xr-x 2 ivan ivan 4096 янв 15 10:05 scripts
-rwxr-x--- 1 ivan dev   512 янв 15 10:07 backup.sh
```

Первая колонка состоит из десяти символов:

```text
-  rwx  r-x  ---
│   │    │    └── остальные (others)
│   │    └─────── группа (group)
│   └──────────── владелец (user)
└──────────────── тип: - файл, d каталог, l ссылка
```

Три буквы в каждой тройке:

| Буква | Право | Для файла | Для каталога |
|---|---|---|---|
| `r` | read, чтение | читать содержимое | видеть список файлов |
| `w` | write, запись | изменять содержимое | создавать и удалять файлы внутри |
| `x` | execute, выполнение | запускать как программу | входить в каталог (`cd`) |

Прочерк означает, что права нет.

Разберём `-rwxr-x---` для `backup.sh`: это файл; владелец `ivan` может
читать, изменять и запускать; члены группы `dev` — читать и запускать;
остальные не могут ничего.

> Право удалить файл определяется правом записи в **каталог**, а не в сам файл.
> Каталог — это список имён, и удаление файла меняет этот список.

## chmod — изменение прав

**Буквенный способ:** кому (`u` владелец, `g` группа, `o` остальные, `a` все),
что сделать (`+` добавить, `-` убрать, `=` установить) и какое право.

```bash
chmod u+x backup.sh          # владельцу добавить право запуска
chmod g-w notes.txt          # у группы убрать право записи
chmod o= secret.txt          # у остальных убрать все права
chmod a+r readme.txt         # всем добавить чтение
chmod -R g+w project/        # рекурсивно для папки и содержимого
```

**Числовой способ:** каждое право имеет вес, веса складываются.

| Право | Вес |
|---|---|
| `r` | 4 |
| `w` | 2 |
| `x` | 1 |

```text
rwx = 4 + 2 + 1 = 7
rw- = 4 + 2     = 6
r-x = 4 + 1     = 5
r-- = 4         = 4
```

Три цифры — для владельца, группы и остальных.

```bash
chmod 644 notes.txt          # rw-r--r--  обычный файл
chmod 755 backup.sh          # rwxr-xr-x  программа или скрипт
chmod 600 id_ed25519         # rw-------  секрет: только владелец
chmod 700 ~/.ssh             # rwx------  закрытая папка
```

Сетевому инженеру числовая запись покажется знакомой: это те же двоичные
разряды. `rwx` = `111` = 7, `r-x` = `101` = 5. Похоже на маски подсетей.

Четыре значения, которые встречаются чаще всего:

| Число | Запись | Где применяется |
|---|---|---|
| `644` | `rw-r--r--` | обычные файлы |
| `755` | `rwxr-xr-x` | программы, скрипты, каталоги |
| `600` | `rw-------` | закрытые ключи, файлы с паролями |
| `700` | `rwx------` | личные каталоги |

## Исполняемые файлы

Чтобы запустить скрипт как программу, ему нужно право `x`.

```bash
echo 'echo "Привет из скрипта"' > hello.sh
./hello.sh                   # bash: ./hello.sh: Permission denied
chmod +x hello.sh
./hello.sh                   # Привет из скрипта
```

Запись `./` означает «в текущей папке». Без неё оболочка ищет программу
только в системных каталогах.

## chown — изменение владельца

```bash
sudo chown ivan notes.txt            # сменить владельца
sudo chown ivan:dev notes.txt        # владельца и группу
sudo chown -R ivan:ivan project/     # рекурсивно
```

Менять владельца может только администратор.

## root и sudo

В системе есть особый пользователь `root`. На него ограничения прав
не действуют: он может прочитать, изменить и удалить что угодно.

Постоянно работать под `root` опасно: опечатка в команде может уничтожить
систему, и никто не спросит подтверждения. Поэтому работают под обычным
пользователем, а отдельные команды выполняют через `sudo`.

```bash
apt update                   # ошибка: недостаточно прав
sudo apt update              # выполнить от имени root
```

`sudo` запросит **твой** пароль. При вводе символы не отображаются —
это нормально. Несколько минут пароль повторно не спрашивается.

```bash
sudo -l                      # что мне разрешено делать через sudo
sudo !!                      # повторить предыдущую команду с sudo
```

Правило: используй `sudo`, только когда понимаешь, зачем команде права
администратора. Если команда из интернета требует `sudo`, сначала разберись,
что она делает.

Это тот же принцип, что и привилегированный режим `enable` на сетевом
оборудовании: повышенные права — только на время конкретной задачи.

## Частые ошибки

- `Permission denied` при чтении файла — нет права `r`, или нет права `x`
  на один из каталогов по пути к нему.
- `Permission denied` при запуске скрипта — нет права `x`.
- `chmod 777` «чтобы заработало» — плохая привычка. Это право на всё для всех.
  Разберись, какого именно права не хватает.

# Практика

**Задание 1.** Выведи своё имя пользователя и список групп. Найди свою запись
в `/etc/passwd`.

**Задание 2.** Расшифруй права: `-rw-r-----`, `drwxr-xr-x`, `-rwx------`,
`-rw-rw-r--`. Для каждой записи назови числовой эквивалент.

**Задание 3.** Создай файл `secret.txt`. Установи права так, чтобы читать
и изменять его мог только владелец. Сделай это двумя способами:
буквенным и числовым. Проверь через `ls -l`.

**Задание 4.** Убери у файла право чтения для себя и попробуй его прочитать.
Верни право обратно.

**Задание 5.** Создай скрипт `info.sh`, который выводит имя пользователя,
текущую папку и дату. Попробуй запустить его, сделай исполняемым
и запусти снова.

**Задание 6.** Создай каталог `locked`, положи в него файл и убери у каталога
право `x`. Попробуй зайти в него и прочитать файл. Потом верни `x`, но убери `r`,
и попробуй вывести список файлов и прочитать файл по имени. Объясни разницу.

**Задание 7.** Попробуй прочитать файл `/etc/shadow` без `sudo` и с `sudo`.
Посмотри его права и объясни, почему он так защищён.

**Задание 8 (со звёздочкой).** Выясни, что такое `umask` и какое значение
установлено у тебя. Объясни, почему новые файлы создаются с правами 644
или 664, а каталоги — 755 или 775.
